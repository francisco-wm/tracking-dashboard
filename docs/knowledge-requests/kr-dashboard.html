Do detected gaps turn into requests?

Decision

Requests can only start from a gap the AI detects in chat, so this is our whole top of the funnel.

If few gaps become requests, the AI flags things people don’t care about, or at the wrong moment: tune detection. If most do, it’s worth letting people start a request without a chat.

Do assignees see their requests?

Decision

Separates “nobody saw it” from “saw it but didn’t answer”. They have different fixes.

If many requests are ignored, the problem is reach: improve notifications to assignees. If they’re opened but not answered, look at the rejection reasons instead.

Why do assignees reject requests?

Decision

Each reason points to a different fix.

Question not clear: help requesters write clearer questions. Don’t know the answer: suggest better assignees. Duplicate or already available: check existing knowledge before a request is sent.

Do teams work as well as naming a person?

Decision

Teams are new. A team never answers; one of its members does. This compares how requests were routed.

If team requests get answered less, people ignore requests not addressed to them by name: nudge requesters to pick a person. If they get answered more, suggest teams by default.

A hint, not proof: vaguer questions might go to teams.

Decision

Shows how fast the first answer arrives, whether requests collect more than one answer, and who writes them.

Decision

Do requesters close the loop?

Decision

The first version deliberately has no reminders and no auto-close. This card tells us if that holds up.

If answered requests pile up without being closed, add a closure nudge or auto-close. If requesters close them reliably, keep it as is.
